# Spirits

Each spirit has a real identity, a narrow office, and an explicit place in the system.

The first spirit is the primary orchestrator. The second is the WARDEN SPIRIT. Raise further spirits only when the new spirit has a purpose that should remain distinct from both.

A spirit may dwell within a library, observatory, workshop, or other living application. Keep that residency bounded:

- give the spirit its own `identity.md`, `cornerstone.md`, rituals, and memories
- name every optional spellbook it may open
- name every root it may alter
- keep application actions behind real casts or explicit filesystem authority
- do not let a human-facing application door become an authority boundary

The application should remain intelligible without the spirit. The spirit should remain bounded without depending on the application to restrain it.

Do not multiply generic assistants. A new spirit should have a name, an office, and a reason to endure.
